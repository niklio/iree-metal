# iree-metal 3.11.0.dev2026080401 — Developer Preview 3

This is the third experimental developer preview of the open iree-metal JAX
backend for Apple GPUs. It remains a prerelease without production support or
an API-stability commitment.

## Highlights

- Native Apple attention now recognizes the causal full-FP32 softmax and VJP
  spelling emitted by JAX 0.6.1 while retaining exact shape, type, mask, scale,
  and use-count proofs.
- Split reductions preserve their workgroup mapping through function codegen,
  handle prime outer dimensions, and use multiple Apple subgroups for large
  non-multiple reductions such as full-vocabulary cross-entropy.
- Non-unique scatter configuration is bounded by the target's exact
  threadgroup-memory limit, including the `bs8 x seq512 x width768` embedding
  gradient.
- Large tied-vocabulary training avoids materializing the full activation
  transpose before weight-gradient matmuls. Canonical
  `sum(logits * one_hot(labels))` selection is rewritten to an indexed mapped
  load, avoiding both the full one-hot temporary and tile-local index errors.
- The packaged `preview-20260804` profile keeps aggressive fusion and Apple
  Metal optimizations enabled, with split reduction enabled by default. Users
  only select `JAX_PLATFORMS=iree_metal`; no per-model flags are required.

## Validation

The release is gated on the physical Apple M4 configuration recorded in the
manifest by four independent verifier lanes:

- 233 BF16/F32 semantic cases, including gather/scatter and target-resource
  invariants;
- nine decoder-training operator/resource cases;
- ten deterministic BF16 Hugging Face model-family forward-and-backward
  workloads; and
- twelve paired decoder-training performance workloads across three model
  families and four training phases.

Every correctness, compilation, resource, determinism, and stability check
must pass. Decoder-training performance additionally requires an overall
geometric-mean throughput ratio of at least 0.95x versus live jax-metal, every
phase at least 0.90x, every workload at least 0.80x, and robust worker CV no
greater than 10%. The attached verifier evidence is authoritative for the
exact wheels.

On the release-gating Apple M4, all four lanes passed: 233/233 semantic cases,
9/9 training operator cases, 10/10 Hugging Face workloads, and 12/12
decoder-training workloads. The measured geometric-mean throughput ratios
versus live jax-metal were 1.0012597001x for the Hugging Face suite and
1.0277517009x for decoder training, both strictly greater than parity.

The comparison is scoped to the disclosed Apple M4, JAX 0.6.1, deterministic
inputs, model shapes, synchronization, and aggregation method. It is not a
claim of universal JAX, model, workload, or Apple GPU parity.

## Supported configuration

- Apple M4
- macOS and Xcode versions recorded in the attached manifest
- CPython 3.12
- JAX/JAXLIB 0.6.1
- Matching compiler and plugin wheels from this release

The `macosx_13_0_arm64` wheel tag is a deployment target, not evidence that the
preview was tested across every macOS 13+ configuration or Apple GPU.

## Numeric and compatibility limitations

The optimized profile's causal-attention bounds assume finite model inputs and
can change NaN/Inf propagation through masked arithmetic. Use
`IREE_METAL_PROFILE=baseline` for non-finite diagnostics. Dynamic shapes,
multiple devices, distributed execution, broad JAX test compatibility, other
Python/JAX versions, and non-M4 Apple GPUs remain outside this preview's claim.

See `docs/metal/developer-preview.md` and `SUPPORT.md` for the complete contract.

## Install

For a normal online installation, install the two wheel URLs shown in the
project README. For an offline or fully auditable installation, use the attached
`iree-metal-preview-3.11.0.dev2026080401-macos-arm64.tar.gz` bundle and verify
its `.sha256` sidecar before extraction.
